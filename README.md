
Итоговое задание 12 спринта выполнено по следующей технологической схеме:
Win 10 => WSL => ubuntu => docker-engine
Win 10 => IDE VS Code

Этапы выполнения итогового задания 12 спринта:
1. Скачен архив (main.go, parcel.go, parcel_test.go, tracker.db)
2. Следуя методологии Infrastructure as Code (Инфраструктура как код), необходимо
    исключить файл БД tracker.db из репозитория Git c помощью файла .gitignore и 
    перенести инициализацию таблиц БД tracker.db непосредствено в runtime-code приложения.
    2.1. Модернизация кода файла main.go.
        2.1.1. Добавлен метод Ping с целью принудительно заставить драйвер SQLite физически
        создать файл tracker.db на диске (если его не было) и установить с ним
        связь.
        2.1.2. Добавлена SQL-инструкцию CREATE TABLE IF NOT EXISTS, которая гарантирует
        безопасный повтоный запуск, автоматически создавая таблицу parcel только при первом
        старте приложения и предотвращая возникновение ошибок или перезапись существующих
        данных при последующих перезапусках контейнера.         
    2.2. Модернизация кода файла parcel_test.go.
        2.2.1. Перевод SQLite в режим :memory: изолирует тесты в оперативной памяти (RAM) и
        исключает дисковый ввод-вывод (I/O), что гарантирует независимость каждого запуска,
        кратно ускоряет выполнение go test и обеспечивает безопасную автоматизацию сборки в
        окружении GitHub Actioins без генерации мусорных файлов БД. 
        2.2.2. В начало каждого теста файла parcel_test.go добавлено автоматическое создание
        таблицы parcel через CREATE TABLE IF NOT EXISTS, что гарантирует наличие необходимой
        структуры в чистой RAM-базе перед каждой проверкой и изолирует тесты от порядка их 
        выполнения.
3. Выполнение инициализации репозитория 12-sprint-final-igor01, настройка отслеживания ветки 
    main (файлы: main.go, parcel.go, parcel_test.go, go.mod, go.sum) для исходного кода проекта
    и настройка интеграции с удаленным репозиторией на GitHub.
4. С целью изоляции процесса разработки и контейнеризации от стабильного исходного кода,  от 
    основной ветки "main" была создана локальная рабочая ветка "first-version".
5. Для интеграции методологии непрерывной интеграции (CI - Continuous Integration) в корень
    проекта добавлен конфигурационный файл .github/workflows/12spr-ci-cd.yml. В рамкам первого 
    этапа автоматизации (CI pipeline) был настроен сценарий для статического анализа 
    исходного кода встроенными линтерами и автоматического запуска модульного тестирования (unit-tests).
6. Добавление файла .gitignore с целью исключения попадания в удаленный репозиторий GitHub
    конфиденциальных данных, временных файлов сборки Go, системных артефактов Ubuntu и 
    и локальной базы tracker.db, что гарантирует чистоту проекта и защищает его от утечки 
    секретов и персональных данных.
